# Set up workflow — initialize dotfiles (or bootstrap a new machine)

Goal: stand up chezmoi-managed dotfiles — either **fresh** (init, bring existing configs under
management, back them with a **private** git repo) or on a **new machine** (init from the existing
repo and apply). Never commit a secret.

> Already initialized and just changing configs? → [upgrade.md](upgrade.md). Something broken
> (apply fails, drift you can't reconcile)? → [repair.md](repair.md). A secret-bearing file? →
> [secrets.md](secrets.md). **New machine** with a repo already? Jump to §8 below.

> Use the `scripts/` toolbox for the mechanical steps: `scripts/chezmoi_status.py` (state check),
> `scripts/dotfiles_inventory.py` (what's managed), `scripts/secret_scan.py` (pre-commit safety).
> The inline bash below is what they run under the hood — reach for it only for one-off checks.

## 1. Confirm state

Run `scripts/chezmoi_status.py`: an `initialized	yes` line means the repo already exists — stop
and switch to [upgrade.md](upgrade.md). `initialized	no` → proceed with init.

<details><summary>Under the hood</summary>

```bash
# `chezmoi source-path` prints a path even when uninitialized — test the repo itself:
test -d "$(chezmoi source-path)/.git" && echo "ALREADY INITIALIZED — use manage/sync, not init"
```
</details>

## 2. Initialize the source

```bash
chezmoi init                       # creates the source repo at `chezmoi source-path`
chezmoi source-path                # usually ~/.local/share/chezmoi (a git repo)
```

## 3. Inventory candidates (add nothing yet)

List config files/dirs that exist and are worth tracking; let the user pick. Common:
`~/.zshenv ~/.zprofile ~/.zshrc ~/.config/fish ~/.config/nvim ~/.gitconfig ~/.tmux.conf
~/.config/starship.toml ~/.config/ghostty` — plus whatever discovery found.

**Screen for secrets first.** Do NOT add files that contain plaintext credentials as-is (e.g.
`~/.gitconfig` signing tokens, tool configs with API keys, anything under `~/.ssh`, `~/.aws`,
`~/.config/*/credentials`). Run `scripts/secret_scan.py <path>` on any file (or dir) before adding
it — it prints offending paths + a reason and never the value. Route flagged files through
[secrets.md](secrets.md).

## 4. Add configs

```bash
chezmoi add ~/.zshrc ~/.zprofile ~/.zshenv
chezmoi add ~/.config/fish ~/.config/nvim ~/.gitconfig
```
chezmoi copies each into the source as `dot_zshrc`, `dot_config/nvim/…`, etc. Review what landed
with `scripts/dotfiles_inventory.py` (each managed target, tagged with its drift status), and
spot-check a source copy against the live file:
```bash
chezmoi cat ~/.zshrc      # verify the source copy matches the live file
```
For files with per-machine bits, consider templating (`chezmoi add --template <file>` →
`.tmpl` with `{{ .chezmoi.hostname }}` etc.). For secret-bearing files, use [secrets.md](secrets.md).

## 5. Add a `.chezmoiignore` and commit

- Create `.chezmoiignore` in the **source root** BEFORE adding directories — `chezmoi add <dir>`
  sweeps in *everything* under it, including cruft. Ignore machine-local, auto-generated, and
  backup files. Starter:
  ```
  # editor / timestamped backups (e.g. from other tooling)
  *.bak
  *.bak.*
  # auto-managed shell state (the shell owns it; churns on upgrades)
  .config/fish/fish_variables
  # files generated by another tool/skill — regenerated per machine, don't carry a stale copy
  .config/fish/conf.d/00-shell-sync.fish
  ```
  (`.chezmoiignore` entries refuse the add, so ignored files never enter the source.)
- **Scan for secrets before the first commit** — run `scripts/secret_scan.py` (exit 0 = clean;
  exit 1 lists paths + reasons to reconcile first; see [secrets.md](secrets.md) §detect), then:
```bash
chezmoi git -- add -A
chezmoi git -- commit -m "Initial dotfiles"
```

## 6. Create the PRIVATE remote & push

```bash
# with gh authed — PRIVATE is important; dotfiles leak secrets when public
chezmoi git -- branch -M main
gh repo create dotfiles --private --source="$(chezmoi source-path)" --push   # confirm name with user
```

## 7. Verify

Run [verification.md](verification.md): `scripts/chezmoi_status.py` should show `status_drift	0`,
`diff_pending	0`, and `doctor ... warning=0 error=0`, and a re-`apply` keeps both counts at 0.
Report what's now managed (`scripts/dotfiles_inventory.py`) and the day-to-day flow
([upgrade.md](upgrade.md)).

## 8. New machine — bootstrap from the repo

Bringing up a **fresh machine** from an existing dotfiles repo (the other setup path):

```bash
# installs from the private repo and applies in one step — OVERWRITES local configs
chezmoi init --apply <github-user>/dotfiles     # or a full git URL
```
On a machine that already has configs, back them up or run `chezmoi init` (without `--apply`) then
`chezmoi diff` to preview before applying. **Prerequisites the templates/encrypted files need must
be present first** — the password manager for secret templates, and the `age`/`gpg` key for
`encrypted_*` files ([secrets.md](secrets.md)); otherwise apply fails on exactly those files (that's
a [repair.md](repair.md) case, not a chezmoi bug). Then [verification.md](verification.md): status
clean, doctor clean, and templated per-host values resolved correctly on THIS machine.
